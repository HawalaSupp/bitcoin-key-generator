# Exodus vs Hawala: Non-App Gaps

This file covers everything Exodus provides that does not live primarily inside the codebase. These are business, operations, support, distribution, trust, and ecosystem gaps.

Scope rules:
- Include things users experience around the product, not just inside it.
- Exclude implementation details that are purely engineering tasks.
- Focus on capabilities Exodus presents as part of the overall product.

## 1. 24/7 Customer Support

Status: `Missing`

Exodus publicly presents support as part of the product experience. Hawala currently positions itself as self-custody without that kind of support layer.

Gap includes:
- staffed support coverage
- support response standards
- ticketing and escalation process
- public support channels
- refund/incident/process handling for third-party provider issues

## 2. Help Center / Public Knowledge Base

Status: `Partial`

Hawala has documentation in the repo, but that is not the same as a customer-facing support center with searchable articles and operational guidance.

Gap includes:
- public help center
- onboarding guides
- troubleshooting guides
- recovery/backup guides
- provider-specific support articles for buy, sell, swap, bridge, staking, and hardware wallets

## 3. Platform Distribution Footprint

Status: `Missing`

Exodus is distributed across desktop, mobile, and browser extension channels. Hawala in this workspace is a macOS desktop product only.

Gap includes:
- App Store presence for mobile
- browser extension store presence
- broader cross-platform product messaging and acquisition funnels

## 4. Commercial On-Ramp / Off-Ramp Relationships

Status: `Partial`

Hawala models multiple fiat providers, but provider modeling is not the same as a complete commercial deployment.

Gap includes:
- production partner agreements
- pricing, rev-share, and jurisdiction coverage
- provider SLAs and commercial contacts
- provider support escalation paths

## 5. Brand Trust Surface

Status: `Partial`

Exodus has a mature public trust layer around the product. Hawala has repo docs but needs a customer-facing trust presence.

Gap includes:
- polished public website trust pages
- security overview pages
- recovery and safety pages
- clear supported-asset and supported-network pages
- public incident communication process

## 6. Formal Mobile Product Presence

Status: `Missing`

Exodus is meaningfully present on mobile as part of its identity. Hawala does not currently have that market footprint.

Gap includes:
- mobile launch plan
- mobile support process
- mobile app store assets and store optimization
- mobile-specific customer education

## 7. Extension Ecosystem Presence

Status: `Missing`

Exodus has a dedicated web3 wallet presence. Hawala does not currently have browser-store presence, extension release process, or extension support policies.

## 8. Compliance / Vendor Operations for Fiat Features

Status: `Partial`

Even if third parties do the regulated flow, Hawala still needs operational readiness around compliance-sensitive providers.

Gap includes:
- provider-country availability matrices
- sanctions/jurisdiction policy coordination
- dispute handoff process
- provider monitoring and replacement process

## 9. Security Audit and Public Assurance Program

Status: `Partial`

Hawala has strong security ambitions, but a consumer wallet competing with Exodus benefits from repeatable external assurance.

Gap includes:
- third-party audits
- publishable audit summaries
- vulnerability disclosure process
- dependency and release security policy

## 10. Lifecycle Operations for a Consumer Wallet

Status: `Partial`

Exodus operates like a shipped consumer product, not just a codebase.

Gap includes:
- release management and rollback process
- support handoffs during provider outages
- service health monitoring
- customer communications during incidents
- release notes and upgrade guidance for users
